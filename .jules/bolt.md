## 2025-02-13 - Avoid unbounded O(N) relational over-fetching in Prisma queries
**Learning:** In Prisma queries, avoid using `include` for relationships that can grow indefinitely (O(N) data like historical logs or completed items) unless properly bounded. Over-fetching this data, especially if silently discarded or when only a count or a specific timeframe is needed, can lead to memory scaling bottlenecks and impact application performance.
**Action:** When a relation is needed, apply `where` filters (e.g., specific date ranges like 'today') directly inside the `include` clause. If the relation data isn't consumed by the client, remove the `include` entirely. If only aggregated data is needed, prioritize database-level aggregations like `count()` over in-memory client-side processing.
