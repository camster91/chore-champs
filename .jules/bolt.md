## 2024-05-18 - Prevent Unbounded Relational Over-fetching in Prisma Queries
**Learning:** Prisma queries that `include` large, unbounded one-to-many relationships (like logs, histories, or assignments) can cause significant backend performance and memory bottlenecks if that data isn't actually returned to the client or used in business logic. In `getKids`, the database was tasked with retrieving and serializing all historical chore assignments and habit logs for every child on every page load, only for the application to immediately discard that data before returning the array of `Kid` profiles to the client.
**Action:** Always verify if `include` relations in Prisma queries are actually mapped or consumed by the returned object, and remove them if they are silently discarded to prevent hidden O(N) memory scaling issues as user histories grow.
## 2024-06-12 - Prevent Unbounded Relational Over-fetching in Prisma Queries
**Learning:** Found an unbounded query issue where Prisma fetches all historical relations (`choreAssignments`, `habitLogs`) when querying `Kid` records on several APIs (`api/dashboard`, `api/kids`, `api/kids/[id]`). The data is later discarded and never used, resulting in an O(N) memory and performance bottleneck as the history data size increases.
**Action:** Always make sure `include` relations in Prisma queries are actually consumed by the response payload or frontend before keeping them, to prevent unnecessary memory and database load.

## 2026-06-25 - Prevent Connection Pool Exhaustion from Sequential Loop Queries
**Learning:** Executing sequential database queries (like `.count()`) inside loops (e.g., iterating over days of the week) can cause massive N+1 query bottlenecks and quickly exhaust database connection pools. In `getWeeklySummary`, what should have been a quick aggregation triggered 21 separate database queries on every page load.
**Action:** Always refactor sequential loop queries into a small number of broad concurrent queries (using `Promise.all` and `findMany` with date ranges) outside the loop, and then filter/aggregate the data in-memory within the loop.
